# 通用面试：准备这 5 题

> 核心项目问题分别保留 12 题。本页只准备开场与跨项目高频问题，不重复展开技术清单。

### C01：请用一分钟做自我介绍。

面试官您好，我叫高俊刚，是郑州大学人工智能专业的研二学生。我主要做过两个项目：一个是自己开发并开源到 GitHub 的 Prism，帮助用户检索真实资料、比较方案并辅助决策；另一个结合加速器科研场景，构建领域知识库，辅助故障排查和案例复用。技术方面，我有多 Agent 编排、RAG 混合检索、MCP 工具接入和后端开发实践，也会通过测试和实际操作核对结果。这次应聘 Agent 开发岗位，是因为方向与我的积累契合，希望参与真实业务中的产品开发与迭代。谢谢。

### C02：你怎样使用 AI 提高开发效率？如何验证生成结果？

先确定最小业务链、输入输出和失败条件，再用 AI 辅助定位代码、设计与实现，自己核对依赖、差异和行为。例如 MCP 接入不能只检查导入 SDK，还要验证工具发现、真实调用、参数与来源时间保留，以及完整业务链确实使用返回结果。之后做相关回归与实际操作，再同步文档；AI 提高实现效率，但完成标准来自可验证的业务结果。

### C03：如果让你探索企业内部 AI Coding 落地，你怎么做？

先选明确任务和试点仓库，建立人工质量、耗时与返工基线，再接入获授权的代码资料和受控工具，分开生成、隔离执行、测试、人工评审与发布。根据任务完成、有效修改、缺陷、审查成本与费用决定是否扩大范围，并补权限、密钥、审计和回滚。这里是设计思路，不应冒充已有企业全链路落地经历。

### C04：人工五百行，AI 写三千行，你怎么看代码冗余？

行数不能单独评价质量，必要测试和契约也会增加代码。但无调用模块、重复状态、多套同义抽象和不必要框架会增加维护成本。应回到最小需求，删除无用功能、合并重复逻辑、复用现有能力，再用业务回归保护重构。重点比较理解与变更成本，而不是盲目追求行数更少或代码更多。

### C05：讲一个你真正解决过的问题，怎样定位和验证？

Prism 曾出现父分支条件改变后后代候选仍显示旧结果的问题。我会从状态与计算链定位，解释显式覆盖与继承字段的区别，再同时检查条件、候选集合和页面结果，覆盖保存与导入。第二个项目中，策略首轮虽然运行成功，但输出点覆盖不全，被外部验收拒绝，反馈修正后才通过。两个例子都说明要验证业务状态和输出契约，不能只看模型文案或退出码。
