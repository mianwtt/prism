# 自主研究修复与真实复测 — 2026-11-15

此前的租房研究失败链路已修复，最终杭州与成都任务各取得 **6 个符合条件、带对应原页主图的整租房源**。这些是新问题触发的真实 Ollama + tofu + LangGraph 调用，输入没有房源链接，没有用旧七套房源、演示数据或生成图片填充结果。

## 修复内容

1. **规划能保留有效需求。** 分离“有原图／有来源”等取证要求与比较维度；模型把查询和约束嵌入 `schema` 时，恢复其结构并继续验证原文约束。不会因此采用固定住房表单、增加默认偏好或猜测数值。
2. **先发现目录，再按条件读详情。** 提示 Agent 用位置、类别、平台组成简短查询，将金额和面积条件用于具体记录筛选。让 Agent 从实际观察到的列表中选择更多详情，并在完整可比较选项不足时补查。已有几个不完整候选不再阻止恢复。
3. **补齐公开移动页与中文编码。** 支持房天下公开移动列表、经纪与个人房源详情，识别 UTF-8／GBK／GB2312／GB18030。保留小数面积，核对 URL 中的房源编号、页面主信息与页内配置是否一致。只取主相册的图片，排除视频封面、户型图和推荐区。
4. **正确处理跳转与访问失败。** 只跟随实际返回的、次数受限的受支持 HTTPS 跳转；详情跳转必须保持同一房源标识。转入登录、校验站点或其他房源时拒绝读取，不解验证码、不登录、不改代理或关闭 TLS 校验。公开桌面与移动来源分别使用它们实际返回的信息。
5. **修复面积单位误判。** `㎡`、`平方米`、`平米`、`m²`、`m2` 按同一面积单位核验；不再把确有引文的面积错误置空。
6. **原图要求贯穿后续对话。** 明确要求原图的任务，只有列表文字但未取得对应图片的记录保留为研究草稿，原文仍可追溯，不冒充完整比较卡片。后续仅修改条件时保留该要求；用户明确撤回时才取消。
7. **研究结果直接接入画布。** Agent 生成并通过校验的 What-if 分支在新结果中直接展开。继续研究时保留原假设与基线，不需要用户到历史菜单里找回首轮建议。
