# Redis 搜索缓存验收 — 2026-11-17

本轮增加可选 Redis 搜索缓存。缓存放在研究工具适配层，复用 tofu/Tavily 搜索结果；JSON 决策版本和 SQLite 检查点保持原职责。

## 已实现

- 按搜索服务、查询、参数、提供者配置指纹和数据目录作用域生成哈希 Key。
- 使用 Redis 服务端 TTL，并在命中时校验格式、原采集时间及当前有效期。
- 在来源入库时保留缓存观察的原采集时间，另记本次提供时间。
- 同进程重复请求合并，关闭命令离线排队，超时/连接/读写异常降级并冷却重试。
- 空结果、搜索异常及超大响应不进入缓存。
- 健康接口提供无密钥、无查询文本的累计计数；闲置连接不阻止 CLI 退出。
- `.env.example` 仅提供 XXX URL；发布检查增加 Redis 凭据 URI 与模板保护。
- Compose 提供可选 cache profile，CI 增加独立真实 Redis 集成任务。

独立正文读取、商家公开标价和引用刷新不缓存。本轮没有增加 Redis 任务队列、分布式锁、模型答案缓存或向量检索。

## 受控重复查询对照

输入为三个不同查询，每个出现三次，共九次请求。外部加载器是固定约 20ms 延迟的测试来源，不调用真实搜索或 LLM。

| 设置 | 请求数 | 外部加载次数 | 最后一轮观测总耗时 |
| --- | ---: | ---: | ---: |
| 不启用缓存 | 9 | 9 | 258ms |
| 启用真实 Redis | 9 | 3 | 111ms |

耗时为一次 Windows 运行观测，受调度与客户端开销影响，不是稳定的性能保证。可复现的关键断言是相同查询的外部加载从九次降到三次。

该结果不能证明实时 tofu 查询具有相同提速比例，更不能证明信息完整率、价格准确率或 Agent 研究成功率提高。首次查询、LLM 推理及独立页面核对仍需执行。

## 搜索技术说明更正

本轮追读了实际安装的 `tofu-search==0.12.25`。Prism 应用未自建 BM25 索引，但依赖默认包含纯 Python BM25 词法重排；当前桥接未开启依赖的 LLM 过滤或本地神经重排器。不能将“应用未自建”概括成“整个搜索链路没有使用 BM25”。详见[技术实现报告](../TECHNICAL-REPORT.md)。

## 后续使用

Redis 默认关闭；在自己的 `.env` 或启动环境设置 `REDIS_URL` 后重启应用即可启用。未配置或 Redis 不可用时仍可执行原搜索。部署、指标与测试命令见[技术实现报告](../TECHNICAL-REPORT.md)和[安装指南](../SETUP.md)。
